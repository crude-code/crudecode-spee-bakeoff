# SPEE Bake-Off Mode

This repo version is specialized for the forecasting bake-off workflow:

1. pass the committee test-data process cleanly;
2. generate a **Strict Auto Forecast** from a preconfigured deterministic DCA algorithm;
3. optionally generate a **Vendor Best Forecast** from completed LLM forecasts or a controlled LLM + strict-auto fallback workflow;
4. keep runtime, failures, and data-boundary checks auditable.

The repo does **not** call the LLM as part of the bake-off command path. Live LLM runs stay in `scripts/run_llm.py`; the Vendor Best command consumes precomputed forecast JSON files.

## Canonical SPEE input

Until the final committee schema lands, normalize any test package into:

```text
spee_data/
  history.csv   # well_id,month,oil,gas,water
  wells.csv     # well_id,pad_id plus optional metadata
  manifest.json # generated by prepare_spee_input.py
```

`history.csv` is long-format monthly production. Missing phases stay blank/NaN, not zero.

Normalize raw committee CSVs:

```bash
python scripts/prepare_spee_input.py \
  --monthly raw/monthly_production.csv \
  --headers raw/well_headers.csv \
  --out spee_data
```

Validate before running forecasts:

```bash
python scripts/validate_spee_input.py spee_data
```

## Strict Auto Forecast

Strict Auto uses one preconfigured deterministic model with no post-run review or manual overrides.

Default run:

```bash
python scripts/run_spee_strict_auto.py spee_data \
  --horizon 12 \
  --out submissions/strict_auto_forecast.csv
```

Optional common forecast start, if the committee specifies one:

```bash
python scripts/run_spee_strict_auto.py spee_data \
  --forecast-start 2026-08-01 \
  --horizon 12
```

Outputs:

```text
submissions/strict_auto_forecast.csv
results/strict_auto_failures.csv
results/strict_auto_failures.md
results/strict_auto_run.json
```

The run log records elapsed seconds, row counts, failure counts, horizon, input path, output path, and model name.

## Vendor Best Forecast

Vendor Best consumes precomputed LLM forecasts. It does **not** make API calls.

```bash
python scripts/run_spee_vendor_best.py spee_data \
  --llm-dir benchmark_data/runs/<run_id>/forecasts \
  --horizon 12 \
  --out submissions/vendor_best_forecast.csv
```

If the workflow policy allows missing LLM rows to fall back to the strict-auto DCA arm, make that explicit:

```bash
python scripts/run_spee_vendor_best.py spee_data \
  --llm-dir benchmark_data/runs/<run_id>/forecasts \
  --fallback-strict-auto
```

The output `model_name` becomes `llm_with_strict_auto_fallback`, so the choice is auditable.

## Validate a submission

```bash
python scripts/validate_spee_input.py spee_data \
  --submission submissions/strict_auto_forecast.csv \
  --horizon 12
```

This checks required columns, valid phases, numeric non-negative forecast volumes, and exactly one row per well/phase/month group for the expected horizon.

## Final committee format

The current CSV is an internal CrudeCode schema:

```text
submission_type,model_name,well_id,pad_id,phase,forecast_month,forecast_volume
```

When the committee publishes final output specs, add a small export adapter rather than changing the scoring/generation core.
